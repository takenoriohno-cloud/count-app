# チラシ配布カウンター 要件定義書

- **文書バージョン**: 1.1.0
- **作成日**: 2026-10-11
- **更新日**: 2026-10-24
- **対象システム**: チラシ配布カウンター Webアプリケーション

---

## 1. システム概要と背景

### 1.1 目的
街頭や店頭等におけるチラシ配布業務において、配布担当者が片手（親指）のみで素早く・正確に属性別配布実績をカウント・記録し、複数メンバーの実績をリアルタイムに集計用Googleスプレッドシートへ集約・可視化できる現場特化型Webツールを提供する。

### 1.2 背景と課題
- 紙のチェックシートや一般的なカウンターアプリでは、両手操作が求められたり、属性の分類（性別×年代）の切り替えが煩雑で配布の瞬間に記録が追いつかない。
- 片手でチラシの束を保持し、もう片方の手（親指1本）でスマートフォンを把持・操作する必要がある。
- 現場終了後または配布中に、「いつ、何時の間に、誰が何枚配ったのか」を即座に本部・現場責任者がリアルタイム集計・把握できる仕組みが必要。

---

## 2. システム構成と技術制約

### 2.1 技術制約
- **完全スタンドアロン構成**: Node.js等のビルド環境や外部Webサーバー処理を必要とせず、単一の `index.html`（HTML/CSS/JS統合）で完結すること。
- **オフライン動作保証**: 屋外や地下等の電波不良環境でもカウント操作が中断・遅延せず、端末ローカルに安全保持されること。
- **ターゲット環境**: iPhone Safari（iOS 15以上推奨）。

### 2.2 採用技術スタック
- **構造/ロジック**: HTML5, Vanilla JavaScript (ES6+)
- **スタイリング**: Tailwind CSS (CDN読み込み) + カスタムCSS (Safe Area対応)
- **音響効果**: Web Audio API (OscillatorNode / GainNode)
- **データ管理**: Web Storage API (localStorage)
- **データ連携**: Google Apps Script (GAS) Web Apps API + Fetch API (非同期通信)
- **外部出力**: Web Share API (navigator.share) + Blob / URL API (フォールバック)

## 3. 機能要件

### 3.1 UI / UX 要件（片手操作特化）
1. **画面レイアウト**
   - **画面上部 (約40%)**: ヘッダー操作部（ステータス・ユーザー名・開始/終了・送信・未送信バッジ）、総配布枚数（特大表示）および属性別リアルタイム集計表。
   - **画面下半分 (約60%)**: 片手把持時の親指可動域に合わせたマトリクス型ボタン群を集中配置。
2. **マトリクスボタン構成 (計12ボタン)**
   - 横2列（男性：スカイブルー系 / 女性：ピンク系）× 縦6行（10代 / 20代 / 30代 / 40代 / 50代 / 60代以上）。
   - 各ボタン内に現在のカテゴリー別小計バッジをリアルタイム表示。
3. **取り消し（アンドゥ）機能**
   - 画面最下部に大きく目立つ「直前の入力を取り消す」ボタンを配置。
   - 直前に入力された属性（性別・年代）と入力時刻をボタン内にプレビュー表示。
   - 記録が0件の場合はボタンを非活性化。
4. **音響・視覚フィードバック**
   - ボタン押下時に Web Audio API により **周波数800Hz・短時間発音（約0.045秒）** の電子クリック音を鳴らす。
   - iOS Safariのオーディオサスペンド制限を解除（初回タッチ時にAudioContext再開）。
   - CSS `:active` による縮小（0.94倍）および瞬間パルス発光エフェクト（`.flash-updated`）。
5. **iOS Safari最適化**
   - Safe Area（ノッチ / ホームバー）対応（`env(safe-area-inset-*)`）。
   - 長押しによるテキスト選択禁止（`user-select: none`）。
   - ダブルタップ拡大防止（`touch-action: manipulation`）。

### 3.2 データ管理要件
1. **ローカル永続化**
   - 1タップごとに以下のデータ構造をJSON配列として `localStorage` に即時保存。
     ```json
     {
       "id": "1773223500123-abcde",
       "timestamp": "2026-10-24T19:05:00.123Z",
       "gender": "男性",
       "ageGroup": "20代",
       "sent": false,
       "status": "valid"
     }
     ```
   - ページ再読み込み時やブラウザ再起動時にも直前の集計・履歴状態を100%復元。
2. **直前履歴の取り消し（アンドゥ）管理**
   - 未送信データを取り消す場合：ローカル履歴配列から該当データを物理削除（スプレッドシートへは一切送信しない）。
   - 送信済みデータを取り消す場合：ローカルの `status` を `"canceled"` に更新し、取消キューに追加。次回送信時にスプレッドシート側のステータスを更新。

### 3.3 Googleスプレッドシート連携・集計要件
1. **端末識別とユーザー名管理 (F-1)**
   - **端末固有UUID (`deviceId`)**: 初回アクセス時にUUIDを自動採番し、`localStorage` に半永久保存。端末を確実に一意識別。
   - **ユーザー名**: 自由記述の入力欄。入力値は `localStorage` に保存し、次回以降自動入力。
2. **送信トリガーと配布制御 (F-2)**
   - **配布開始 / 終了ボタン**: 配布中と停止中の状態をトグル管理。
   - **定期自動送信**: 配布中状態のみ、15分間隔でバックグラウンドにて未送信データを自動送信。
   - **手動即時送信**: いつでも手動で未送信データを即時送信可能。
   - **終了時セーフティ**: 配布終了ボタン押下時に未送信データが存在する場合、最終送信の確認・実行を行う。
3. **明細ログ送信 (F-3)**
   - 集計の柔軟性を担保するため、サマリーではなく1枚ごとのタイムスタンプ付き明細ログを配列で送信。
4. **送信ステータスと未送信バッジ (F-4)**
   - 画面ヘッダー部に「未送信：○件」バッジを表示。
   - 送信中はインジケータ（スピナー）を表示し、送信成功でバッジが0件に更新。送信失敗時はエラー通知と再送待機。
5. **スプレッドシート構成 (F-5)**
   - **生データシート (`raw_logs`)**: 送信された全明細（レコードID, 日時, 端末ID, 名前, 性別, 年代, ステータス, 受信日時）を時系列追記。
   - **ダッシュボードシート (`dashboard`)**: ピボットテーブルまたは `QUERY` 関数を用い、`ステータス = "有効"` のデータから「メンバー別 × 時間帯別（1時間単位）」の配布枚数マトリクスを即座に自動集計。

### 3.4 データ出力・リセット要件
1. **CSVエクスポート**
   - **文字コード**: Microsoft Excelで開いても文字化けしない **BOM付きUTF-8 (`\uFEFF`)**。
   - **出力項目**: `No`, `日時`, `性別`, `年代`, `ステータス`
   - **共有インターフェース**:
     - `navigator.share`（Web Share API）による iOS共有シート呼び出しを最優先実行。
     - 非対応環境またはキャンセル時は Blob URL を生成して自動ダウンロードへ代替。
2. **2段階確認データリセット**
   - 屋外操作時の誤タップによるデータ消失を防ぐカスタムモーダルUI。
   - **Step 1**: 消去対象件数の表示と注意喚起。
   - **Step 2**: 最終実行確認（「完全に消去する」タップで消去実行）。
   - モーダル外タップまたはキャンセルボタンで安全に中止可能。

## 4. 非機能要件

| 区分 | 要件詳細 |
| :--- | :--- |
| **アーキテクチャ** | サーバー構築不要で無料運用可能な **Google Apps Script (GAS) Web Apps** をAPIとして活用 |
| **応答性** | 送信処理は完全非同期（`async/await`）で実行し、送信処理中もカウント入力や音声フィードバックを 50ms 以内で維持（UIブロックなし） |
| **データ保証・整合性** | GASから正常応答（HTTP 200 & success）を受信するまで未送信フラグを解除せず、オフライン時・通信障害時のデータ欠落をゼロ保証 |
| **排他制御** | 複数メンバーが同時に送信した際の競合・上書き抜けを防ぐため、GAS側で `LockService.getScriptLock()` による排他ロック制御（最大30秒待機）を実施 |
| **セキュリティ・認証** | リクエストボディに事前共有した `apiToken`（シークレットキー）を含め、GAS側で厳密に照合 |
| **運用制御** | 配布終了後はGAS側のWebアプリ公開設定を非公開（またはアーカイブ）とすることで受信を安全に停止。アプリ側は受付終了メッセージを分かりやすく通知 |
| **可読性・視認性** | 直射日光下や薄暗い屋外でも視認しやすい高コントラストダークテーマ（Slate-950ベース） |
| **保守性** | 外部依存をTailwind CDNとGoogle Fontsのみに限定し、単一HTMLファイルとしての可搬性を維持 |
